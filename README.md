# پایش‌بان — سامانهٔ ممیزی سالانهٔ پتروشیمی‌های عسلویه

داشبورد فارسی و راست‌به‌چپ برای ثبت، پایش و گزارش ممیزی شرکت‌های پتروشیمی در پنج حوزهٔ محیط‌زیست، بهداشت، ایمنی، مدیریت بحران و آتش‌نشانی.

## وضعیت نسخه

- **محیط‌زیست:** چک‌لیست بندبه‌بند از شیت مبنا وارد شده است. برای ۱۲ شرکت که ریزنمره در فایل داشتند، پاسخ هر بند پیش‌بارگذاری شده؛ نمرهٔ محاسباتی هرکدام با نمرهٔ نهایی شیت کنترل و برابر است.
- **فهرست شرکت‌ها:** هر ۳۱ نام از شیت اول آمده است. برای ۱۹ شرکتِ فاقد ریزنمره، ارزیابی سال ۱۴۰۴ و سال‌های بعد از صفر آغاز می‌شود؛ نتیجهٔ هر بند و نمرهٔ کل اولیه صفر است و نمرهٔ کل با مجموع (نتیجه × وزن) از نو محاسبه می‌شود. نمره‌های سال ۱۴۰۳ برای حفظ سابقه تغییر نمی‌کنند.
- **بهداشت، ایمنی، مدیریت بحران و آتش‌نشانی:** بدون بند یا امتیاز اولیه؛ کاربر می‌تواند بندهای اختصاصی هر حوزه را اضافه کند.
- **مدیریت بندها:** در هر بخش امکان افزودن بند جدید، ویرایش متن/دسته/وزن پایه و حذف بند با تأیید وجود دارد. حذف بند در فضای کاری مشترک همگام می‌شود.
- **فرمول امتیاز:** امتیاز هر بند = «نتیجهٔ ارزیابی × وزن بند» و نمرهٔ کل = مجموع امتیاز بندها. هر دو مقدار کنار همان بند قابل ویرایش‌اند؛ نتیجه بین ۰ و ۱ است و با تغییر نتیجه یا وزن، امتیاز بند و کل فوراً محاسبه می‌شود.
- **سال‌های ممیزی:** سال جاری هجری‌شمسی و ۱۰ سال پس از آن به‌طور خودکار در فهرست نمایش داده می‌شوند؛ سال‌های گذشتهٔ موجود نیز حفظ شده‌اند.
- **گزارش:** گزارش هر حوزه شامل نمودار مقایسهٔ شرکت‌ها و جدول تفصیلی شرکت×بند است. در پنجرهٔ چاپ مرورگر، «ذخیره به‌صورت PDF» را انتخاب کنید.
- **افزودن بند به دسته:** دکمهٔ افزودن در انتهای فهرست هر دسته/عنوان قرار دارد و فرم، همان عنوان را انتخاب می‌کند.

## Supabase و همگام‌سازی

پروژهٔ Supabase با شناسهٔ `dpdgjehodzawkriezbvi` در منطقهٔ `ap-south-1` از طریق پلاگین Supabase ساخته و schema آن اعمال شده است. جدول `public.audit_workspace` یک فضای کاری مشترک نگه می‌دارد؛ کاربران مجاز پس از ورود تغییرات نمره، وزن، سال و بندها را در فضای ابری ذخیره می‌کنند و Supabase Realtime تغییرهای دیگر اعضا را دریافت می‌کند. نسخهٔ localStorage نیز برای پشتیبان‌گیری/بازیابی در همان دستگاه باقی می‌ماند.

صفحه بدون ورود فوراً باز می‌شود و در حالت مهمان داده‌های اولیه را نمایش می‌دهد؛ تغییرهای مهمان فقط در localStorage همان مرورگر می‌مانند و با همکاران همگام نمی‌شوند. دکمهٔ «ورود برای همگام‌سازی» ورود ایمیلی را به‌صورت اختیاری ارائه می‌کند. دسترسی به workspace ابری با RLS محدود است: فقط ایمیل‌های ثبت‌شده در `public.audit_access_allowlist` می‌توانند داده‌های مشترک را بخوانند یا ویرایش کنند. فهرست مجاز فعلاً خالی است؛ برای فعال‌شدن همگام‌سازی، مدیر باید ایمیل خود و همکاران مجاز را ثبت کند.

**تنظیم اختیاری لینک ورود در Supabase:** اگر همگام‌سازی ابری می‌خواهید، در داشبورد Supabase به Authentication → URL Configuration بروید، Site URL را روی `https://audit-jade-three.vercel.app` بگذارید و `https://audit-jade-three.vercel.app/` را به Redirect URLs اضافه کنید. برای توسعهٔ محلی می‌توان `http://localhost:8000/**` را نیز افزود. تنظیم Auth از پلاگین Supabase در دسترس نیست.

`js/supabase-config.js` فقط URL پروژه و کلید عمومی نوع publishable را نگه می‌دارد. کلید service-role محرمانه است و نباید در مرورگر، GitHub یا Vercel static files قرار گیرد.

## اجرا

سایت استاتیک است و نیاز به build ندارد. در ریشهٔ مخزن:

```bash
python3 -m http.server 8000
```

سپس `http://localhost:8000` را باز کنید. برای ورود محلی، URL لوکال باید در Redirect URLs مجاز باشد.

## استقرار روی Vercel

مخزن GitHub را در Vercel متصل کنید و این تنظیمات را انتخاب کنید:

- Framework Preset: **Other**
- Build Command: خالی (یا `true`)
- Output Directory: `.`
- Install Command: خالی

پس از هر push به شاخهٔ متصل‌شده، Vercel استقرار تازه می‌سازد.

